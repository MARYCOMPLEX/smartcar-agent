# 验证记录与边界

## 仓库可运行性

仓库带有 Windows 安装检查和 CI：按 `uv.lock` 新建环境，验证原始输入哈希，实际执行 CAD STEP 导入导出、Manifold 体积、Embree 射线、CP-SAT 和 PNG 渲染，再执行完整几何单元回归与默认模型分析。

安装报告写入 `reports/install_check.json`，pytest 可通过 `test.cmd -q --junitxml=reports/tests.xml` 保存记录。CI 验证软件运行，并不认证每个输出小车可制造。

2026-09-10 已从私有 GitHub 仓库重新克隆到独立目录，创建全新 `.venv`，没有复制旧硬件缓存。普通安装实测 256.95 秒，包含当次依赖下载与原生运行检查；24 份随附输入文件与原始字节完全一致。本地 96 项测试全部通过（117.46 秒，0 失败、0 跳过）。第三方 scikit-image 在 NumPy 2.5 下的弃用提醒仍显示，没有为测试通过而屏蔽。

GitHub Windows 检查同样完成 96 项测试和默认模型分析、真实硬件导入：[首轮检查](https://github.com/MARYCOMPLEX/smartcar-agent/actions/runs/34475577538)、[安装兼容性修复后的检查](https://github.com/MARYCOMPLEX/smartcar-agent/actions/runs/34476047589)。[强制首次安装检查](https://github.com/MARYCOMPLEX/smartcar-agent/actions/runs/34476981022) 移除 PATH 中的 Python/uv，成功自动准备 Python 3.12.13，96 项测试在 45.297 秒内全部通过，并完成默认模型分析。

本地同样在带空格的目录、无 Python/uv 命令、空 Python/包缓存条件下复测；自动安装 Python 3.12.13 和全部依赖，原生检查通过。此次网络下载较慢，修复后重试用时 1117.08 秒（复用了此前已经下载、重新校验的 uv 压缩包）。后续启动同步检查不到 1 秒。安装耗时主要受缓存和网络影响，不应把某次时间当作保证。

另外从项目外目录传入带空格的相对 STL 路径，确认实际加载成功；刻意给出零目标长度，正式 pipeline 正确返回 `INVALID_TARGET_LENGTH` 和退出码 2，启动器没有吞掉参数或错误。五份真实 STEP/STP 在含空格的绝对路径下也逐份通过原生导入。批量启动器帮助命令已验证。

默认模型的新目录复测完成了输入分析、真实 CAD 导入、1.9 倍布局搜索、上壳/底盖/电机压板建模、装配路径和第一候选的完整几何验收。该候选为 **206 PASS / 1 FAIL / 23 WARNING**（最终输出导出阶段之前的检查计数）；失败为 `wall_thickness:body`：180,836 条射线中 33 条低于要求，最小 0.135314 mm，要求 1.6 mm。

机器可读的软件/CI验证记录、已复现的几何失败及原报告摘要见 [clone-verification.json](clone-verification.json)。以上软件测试数字不能替代工程验收状态。
